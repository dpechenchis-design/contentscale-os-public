# Format guides: що потрібно для кожного Type

Загальне для всіх:
- Референс береться з `reference_records.json`: `passes_ratio = true` (або виняток, погоджений CM), `approval_gate = OK`, `type` визначено за кадрами (`type_status = CLASSIFIED`).
- **Type поста = Type референсу.** Expert video не перетворюється на Talking head, BTS — на скрипт. Якщо клієнт не може відтворити Type (Working Model, асети) → **інший референс**, а не інший Type.
- Тема = біль, заперечення чи бажання клієнта з контексту (`evidence_map`). Головне заперечення (`core_objection`) не підмінювати схожим.
- Структура референсу зберігається 1:1: hook skeleton → build-up → payoff → CTA (якщо був). Не губити build-up і не відповідати на hook одразу.
- Hook: та сама структура, 1–2 слова змінено під клієнта. Заява правдива для клієнта.
- Notes for the client: конкретні дії (що зняти, у чому, що показати, що сказати), без «чому» і без внутрішніх приміток.
- Caption: освітній, кожне слово несе цінність. Без продажного тону, якщо пост освітній. Хештеги за патерном клієнта (the client: `#brand #brandname`).

## Talking head
- Потрібно: транскрипт референсу (SortFeed / Whisper), факти клієнта для підстановки.
- Робота: метод 1:1 reskin (`$CS/cs-two-week-calendar/references/viral_1to1_reskin.md`). У внутрішньому файлі зберегти **дві колонки: оригінал | клієнт** біт-в-біт. У Notion іде лише колонка клієнта.
- Якщо транскрипту немає (`TRANSCRIPT_MISSING`) → TH не писати; спершу отримати транскрипт (`fetch_media.py`).
- Тільки факти клієнта. Немає факту для біта → питання CM (voice note), не вигадка.
- Creator skills (SOP): лише коли референс-відео немає, а тема потрібна стратегії. Тоді один creator, slot-by-slot QC.

## Re-record власного хіта (TH або BTS) — рішення CM 2026-10-13
- Коли: власний пост клієнта пройшов 2× і `new_recordings_allowed = true`.
- **Хук той самий** (дослівно), **скрипт трохи змінений**: ті самі біти й порядок, інші приклади чи формулювання. Тема і структура не міняються.
- Внутрішньо: таблиця `оригінал | нова версія` у `reskin/<id>.md`, як для будь-якого Talking head. У Notion іде SCRIPT = нова версія.
- NOTES: «перезапиши це відео» + що змінити в кадрі (сетинг, одяг, ракурс), без пояснень «чому».

## Об'єкт реакції: відгук
- Окремий відгук (review widget тощо) часто не має власного URL. Тоді `reaction_target_url` = сторінка продукту, а дослівна цитата відгуку з ім'ям чи датою йде в NOTES. Такий запис вважається реальним об'єктом реакції.

## Expert video (= Expert Reaction)
- Потрібно: **конкретний об'єкт реакції** — реальне відео, коментар, відгук чи claim конкурента з URL або скриншотом (`reaction_target_url`). Об'єкт брати з research, з реальних відгуків/коментарів (review widget, TikTok-коментарі, Google reviews) або з відео в ніші.
- Callout: `Reference` (формат) + `React to this video:` (об'єкт).
- NOTES: «Запиши реакцію на це відео, як у референсі» + точний фрагмент (таймкод/цитата) + 3–5 talking points із фактів клієнта.
- SCRIPT не потрібен. Позицію клієнта не вигадувати: talking points лише з контексту.
- Немає об'єкта реакції → пост не робимо, беремо інший референс.

## BTS
- Потрібно: on-screen текст з кадрів референсу (hook + кроки), можливість зняти (B-roll, продукт, люди).
- NOTES: кроки зйомки точно як у референсі (за кадрами). Нічого, чого немає в референсі (кейс: «миття» в стайлінговому референсі — брак).
- ON-SCREEN TEXT: послідовність плашок. **Spoken script — ні.**
- `EXISTING_ONLY` і немає B-roll → не включати.
- Продукт референсу, якого в клієнта немає → той самий крок з найближчим продуктом клієнта за призначенням (див. `cs-post-writer` 3a); немає відповідника → інший референс.

## Carousel
- Потрібно: carousel-референс (`Carousels` у research), текст **кожного** слайду по порядку, slide 1 = hook, фінальний слайд, caption.
- Факти на слайдах — лише з контексту.
- Тільки caption без слайдів → брак.
- Тип `Carousel` ставити лише для платформ, де стратегія його дозволила (the client: каруселей немає).
