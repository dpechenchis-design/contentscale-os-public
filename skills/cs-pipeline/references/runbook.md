# Runbook для Content Manager: від Unpacking до календаря

Інструкція для людини: що підготувати, що скаже Claude, де твоє рішення обов'язкове, що робити, коли щось пішло не так.
Почни в Claude Code у робочій папці ContentSCALE: «новий клієнт <назва>, запусти пайплайн» (скіл `cs-pipeline`).

---

## 0. Один раз на комп'ютері
| Що | Як |
|---|---|
| Python-середовище | `sh $CS/cs-pipeline/scripts/setup.sh` |
| yt-dlp, ffmpeg | `brew install yt-dlp ffmpeg` (setup підкаже, якщо їх немає) |
| Конектори Claude | Fathom, Notion, Canva: увімкнені й авторизовані |
| SortFeed Pro | Розширення в Chrome, вхід у Pro |
| Canva | Доступ до `ContentSCALE — Strategy Master` (поділитися з акаунтом CM) |

---

## 1. Client Context (~15 хв роботи Claude)
**Ти даєш:** посилання на запис Unpacking у Fathom (або файл транскрипту). За наявності — сайт клієнта, брендові матеріали, ICP-документи.
**Claude робить:**
- зберігає транскрипт дослівно;
- витягує факти з джерелами: продукт, аудиторію, болі, заперечення, бажання, конкурентів, асети;
- визначає Working Model (ACTIVE / LIMITED / EXISTING_ONLY / UNKNOWN);
- збирає публічні відгуки;
- будує досьє в структурі reference client dossier;
- перевіряє, що кожна цитата справді є в транскрипті.

**Тебе спитають:** лише критичне, наприклад «чи зніматиме клієнт нове?», якщо в дзвінку цього немає.
**Ти перевіряєш:**
- досьє (Artifact);
- список «spot-check у Fathom»: цитати, у яких Fathom переплутав спікера (часто слова клієнта записані під іменем Head of Content). Переслухай вказані таймкоди.

**Готово, коли:** перевірка цитат = 0 помилок, досьє погоджене.

---

## 2. Content Research (автоматично: TikTok через yt-dlp, Instagram через твій Chrome; ~5–20 хв Claude)
**TikTok:** Claude сам збирає профілі клієнта й конкурентів (0 кредитів). **Instagram:** Claude читає профілі у твоєму Chrome (будь залогінена в Instagram). **SortFeed вручну лише як запасний варіант:**
1. Відкрий профіль клієнта чи конкурента: TikTok → Videos; Instagram → Reels (для каруселей ще й Posts).
2. SortFeed → Sort by Views → дочекайся, поки завантажаться пости.
3. (Pro) Transcribe для топ-постів.
4. Export → Excel → поклади файл **без змін** у `clients/<slug>/sources/sortfeed/`.

**Конкуренти:** якщо клієнт назвав їх на дзвінку, Claude бере їх без погодження. Якщо Claude знайшов їх сам, він покаже список, і ти кажеш approve/reject **до** експорту.
**Підписники:** SortFeed їх не експортує, тож Claude бере їх із профілів, а ти підтверджуєш.
**Claude робить:**
- застосовує правило «перегляди ≥ 2× підписники»;
- заповнює канонічну research-таблицю (ті самі вкладки + `Carousels`);
- для shortlist завантажує кадри й транскрипти, визначає Type.

**Ти робиш:** ставиш `Approved?` у таблиці. Claude його ніколи не ставить.
**Знай:** у великих брендів (мільйони підписників) правило проходить мало постів. Виняток вирішуєш ти, і він фіксується в лозі.

## 3. Content Strategy (~20 хв Claude)
**Тебе спитають, якщо цього немає в Unpacking:**
- cadence по платформах (обов'язково);
- дозволені Types;
- 3–4 категорії Format;
- бізнес-цілі з цифрами (якщо клієнт їх не називав, цифр не буде).

**Claude робить:**
- fact map для кожного розділу reference-структури;
- текст із джерелами;
- AI-slop;
- автоматичну перевірку (жодних слів з інших стратегій, cadence є, усі плейсхолдери заповнені);
- копію майстра в Canva, заповнену текстом і фото з сайту клієнта.

**Ти:** дивишся прев'ю в Canva → «так» → Claude зберігає. Без «так» нічого не зберігається.
**Знай:**
- Canva-коннектор не міняє шрифт, а текст після жирної мітки іноді стає жирним. Claude назве такі місця, а виправити їх — один клік вручну.
- Клієнтські фото тільки з сайту клієнта або наданих матеріалів.

---

## 4. Two-week Calendar (~10 хв Claude на день)
**Claude робить:**
- план 14 днів за cadence і міксом категорій стратегії;
- для кожного поста — реальний референс із research (Type = Type референсу), перевірку, що клієнт може це відтворити, і текст за правилами Type.

| Type | Що буде в картці |
|---|---|
| Talking head | SCRIPT за структурою референсу 1:1 (внутрішня таблиця оригінал \| клієнт) |
| Перезйомка свого хіта | той самий хук, трохи змінений скрипт |
| Expert video | посилання «React to this video» на реальне відео чи відгук + talking points, без скрипта |
| BTS (включно зі скетчами без мовлення) | кроки зйомки з кадрів + текст на екрані, без скрипта |

- Caption освітній, з хештегами клієнта.
- Перевірка: 18 regression-тестів із фідбеку Head of Content.

**Ти:**
1. Claude пише **1 тестову сторінку** → ти дивишся → «так».
2. Далі він записує день за днем, ти переглядаєш кожен день.

**У Notion завжди:** Status `Script ready`, Publishing date і Edited video порожні, жодних пояснень у тексті.

---

## Коли ескалювати до Head of Content / Head of Content
- Клієнт не дає ні нових зйомок, ні архіву (`EXISTING_ONLY` без асетів): календар нема з чого будувати.
- Протиріччя між тим, що клієнт сказав на дзвінку, і тим, що пише зараз.
- Потрібен виняток із правила 2× або формат, якого немає в стратегії.
- Юридичні питання: згоди, неповнолітні, claims про здоров'я.

## Часті проблеми
| Симптом | Що робити |
|---|---|
| TikTok у Chrome показує «Please wait…» | Відкрий TikTok вручну один раз (перевірка від ботів); Claude її не обходить |
| Транскрипт «немає мовлення», а людина говорить | Скрипт сам повторює розпізнавання без фільтра тиші. Якщо й далі порожньо, використай Transcribe у SortFeed |
| Canva: «Not allowed to access design» | Дизайн належить іншому акаунту → Share на акаунт, підключений до Claude |
| Чернетка Canva «зникла» | Незбережена транзакція в Canva живе обмежений час. Попроси Claude перезібрати копію |
| Notion: текст з `$` відображається дивно | Скрипт сам екранує `$`. Якщо писали вручну, додай `\$` |
| Fathom переплутав спікерів | Нормально. Цитати перевіряються за змістом, CM переслуховує позначені таймкоди |
