# Quality bar: як виглядає «добре» і що вважається браком

Агент `cs-quality-reviewer` і кожен етап звіряються з цим файлом. Брак = результат не йде до CM, доки його не виправлено.

## Скрізь
| Добре | Брак |
|---|---|
| Кожен факт, цифра, цитата мають джерело (дзвінок з таймкодом, сайт, research, CM) | Будь-що вигадане: цифра, кейс, цитата, коментар, відгук, продукт |
| Конкретика клієнта: назви продуктів, справжні заперечення, реальні цифри research | Generic-маркетинг, фрази, що підходять будь-якому бренду |
| Живий текст без AI-маркерів | `—` для драматизму, `« »`, «here's the thing», «it's not X, it's Y», «unlock/elevate», трійки-ритми, повтори між постами (`banned_phrases.md`) |
| Клієнтський документ без внутрішнього | «AI вирішив», пояснення стратегії в календарі, QA-примітки, ID, `{{ }}` |
| Правила клієнта виконано (`client_rules.md`) | Заборонений продукт, хештеги видалені чи вигадані, порушений claim |

## Етап 1. Досьє
- **Еталон:** reference client dossier. 23 розділи, дослівні цитати клієнта з іменем і дзвінком, синтез позначений `INTERP`, Part III на реальних відгуках.
- **Брак:**
  - цитата агенції подана як голос клієнта;
  - цифра в `stat` без джерела;
  - Part III з «приблизними» даними;
  - Working Model за замовчуванням ACTIVE.

## Етап 2. Research
- **Добре:** таблиця з тими самими вкладками; тільки пости, що пройшли 2×; `Approved?` порожнє; shortlist має Type з доказом за кадрами.
- **Брак:**
  - пост без URL;
  - метрика «на око»;
  - Type за назвою чи caption, а не за кадрами;
  - конкурент без погодження CM, якщо його знайшов AI.

## Етап 3. Стратегія
- **Еталон рівня:** затверджена стратегія the client (`<CANVA_DESIGN_ID>`). Communication goals навколо головного заперечення, pillars з % від реальних топ-постів, поетапний план «спершу те, що працює», хуки з болів клієнта.
- **Брак:**
  - немає cadence;
  - pillars не збігаються з Format календаря;
  - цифри цілей, яких клієнт не називав;
  - слова чи факти іншого клієнта;
  - порожні слоти або `{{`;
  - «İ» в заголовках.

## Етап 4. Календар (див. також 18 regression-тестів)
- **Еталон картки (Notion):** 🎯 callout Reference (`@акаунт, NK views`) [+ `React to this video`] → NOTES FOR THE CLIENT (конкретні дії) → SCRIPT (лише TH) / ON-SCREEN TEXT (BTS) → CAPTION з хештегами клієнта.
- **Хук:** перше речення, біль ICP, структура референсу 1:1, правдивий для клієнта (Head of Content 1.1–1.8).
- **Скрипт:** структура референсу біт-у-біт; build-up перед відповіддю; ~25–90 с; без вигаданих фактів (2.1–2.5).
- **Caption:** трейлер, а не переказ; освітній; один CTA, якщо він є в референсі; хештеги клієнта (3.1–3.8).
- **Брак (траплявся в реальному календарі):**
  - Expert video без відео для реакції;
  - BTS зі скриптом;
  - кроки BTS, яких немає в референсі;
  - підмінене головне заперечення;
  - вигадана проблема;
  - продажний caption в освітньому пості;
  - дати;
  - однакові назви;
  - пояснення в картці.

## Тон звіту для CM (як у Head of Content)
- Нумерований список.
- Конкретний фікс із готовою заміною.
- Пояснення через глядача або клієнта, а не «так треба».
- Спершу відповідь на питання, потім деталі.
