# dan-martell-shortform — короткие виральные скрипты + медиа-движок Дэна Мартелла

Полный ассет: система-промпт (пишет скрипты) + методология Sam (объясняет почему работает). Short-form.
YouTube-версия придёт отдельным скиллом. Hormozi — тоже отдельно.

## ⚠️ ДЖЕРЕЛО ДАНИХ — жорстке правило

Усі рілсів для роботи беруться **ТІЛЬКИ з бази цього скіла**. Інших джерел немає.

- `references/reels-database.md` — 100 рілсів @danmartell: посилання, дата, перегляди, лайки, коменти, фоловери і **повний дослівний транскрипт**. Відсортовано за переглядами.
- `references/reels-table.xlsx` — оригінальна таблиця (ті самі дані; картинки винесені в `visuals/`, щоб скіл важив мало).
- `references/visuals/<shortcode>.jpg` — скрін формату і хука на екрані (100 з 100). **Перед вибором рілса відкрий його скрін (Read) і подивись**: формат зйомки (talking head / split-screen / вулиця / BTS / текст на екрані), текст хука в кадрі. Формат у примітці ресогу пишеш за скріном, а не вгадуєш з транскрипту.

Правила:
1. Посилання, метрика, транскрипт — **копіюються з бази дослівно**. Не округлювати (4,549,912, не «4.5M»), не переказувати, не скорочувати транскрипт — ліва колонка ресогу = ВЕСЬ транскрипт, біт за бітом.
2. Не скрейпити і не шукати рілси інструментами (vidIQ тощо), не брати приклади «з пам'яті» — поки у базі є потрібне.
3. `BTS` / порожній транскрипт / пісня / не англійською = без мови креатора → для 1:1 ресогу не годиться (хіба скелет повністю в тексті на екрані — тоді дивись скрін).
4. Метрика — на дату вивантаження таблиці; у доці так і підписувати.
5. `references/viral-frameworks.md` / `framework.md` — для назв фреймворків і розуміння скелетів, **не** як джерело оригінального тексту.

## Референсы
- **system-prompt-25-bangers.md** — дословный system prompt: OUTPUT FORMAT (Question→Hook[type]→Explain→
  Illustrate→Lesson→Hook2[type]), 5 типов хуков (Contrarian/Labeling/Curiosity Gap/Reframe/Pattern Interrupt),
  non-negotiable правила, CCN-тест тем.
- **media-engine.md** — методология Sam: 3 части движка, знай клиента (4 вещи + имя аватара), 3 Ps,
  banger = Problem+Lesson+Story, story = Actions+Feelings+Tension, 6-шаговый воркфлоу, бакеты, платформы, команда.
- **sam-illustrate.md** — вариант скелета Sam (Hook-триггер→proof-action→thesis→bridge→phases-с-механизмом→
  payoff-математика→lesson), для контента типа «фазы/система».
- **sam-voice-style.md** — голос и обороты Сэма из 4 его видео (открытие-триггер, walkthrough 2-е лицо,
  механизм-first, предвосхищение вопроса + авторитет, фазы, payoff-математика, ставка, «no bullshit»
  закрытие, story-craft). Референс КРАФТА/РИТМА; личность/лексика = ToV клиента (слой сверху).

## Два режима
1. **Bulk «25 bangers из ниши»** — вход: ниша. По CCN-тесту найти нюансные темы → скрипты строго в OUTPUT
   FORMAT. Перед выдачей: прогнать через ДНК клиента (Hopes/Dreams/Fears/Blockers, дать имя аватара) + banned-phrases.
2. **Один скрипт под карточку** — вызывается из script-factory: движок задаёт СКЕЛЕТ + типы хуков, фактура
   из ДНК/voice notes клиента. Разметка блоков inline.

## Обязательное перед скриптами (из media-engine)
- Знай 4 вещи о клиенте и бей в них в первые 30 сек: Hopes, Dreams (в хук) + Fears, Blockers (подсадка).
- Каждое видео = один Clear Problem + Lesson/модель («briefcase») + Story с Actions/Feelings/Tension.
- Аутлайн через 3 Ps: Proof (часто показать, не сказать), Promise (чёткое), Plan (road map).
- Темы: часть — из sales calls / вопросов клиентов; ломать нужные для покупки убеждения.

## ⚠️ Конфликт с баном Дарины (флаг, решение ждёт)
Промпт требует «That's not an X problem. That's a Y problem» в ILLUSTRATE + эхо в Hook2. Дарина забанила
(«звучит как ChatGPT»). До решения: держим МЕХАНИКУ диагностической строки, но живее (semicolon-контраст
в его же стиле: «You don't have an idea problem; you have a courage problem»).

## Честность (правило системы поверх движка)
Хук-скелет 1:1, заявка = правда для клиента сейчас; не присваивать чужой результат/виральность.

## Режим: 1:1 Viral Reskin (два стовпці)

Коли команда дає конкретне віральне відео як референс, Claude виконує повний 1:1 реског замість генерації з фреймворку.

### Процес
1. Взяти рілс з `references/reels-database.md` (або той, що назвала команда, — теж шукати в базі): посилання, метрика і ДОСЛІВНИЙ повний транскрипт звідти. Подивитись його скрін у `references/visuals/`.
2. Розібрати скелет построково: кожен рядок = окремий біт (хук, приклад, число, CTA).
3. Переписати рядок-в-рядок, підставляючи змінні під клієнта: нішу, приклади, числа, CTA.
4. НЕ додавати / НЕ прибирати / НЕ міняти порядок бітів.

### Головне правило
**Віральний хук залишається 1:1.** Хук не змінюється — змінюється ТІЛЬКИ контекст під клієнта. Структура вже доведена переглядами; міняємо лише змінні (ніша, приклади, числа, CTA keyword).

### Формат виводу: шапка + таблиця з двох колонок

**Шапка (завжди перед таблицею):**
> **Референс:** [назва/опис відео](посилання на оригінал) | **Views:** X | **Likes:** X | **Creator:** @handle

| Original | Версія під клієнта |
|---|---|
| [біт 1 оригіналу дослівно] | [біт 1 під клієнта] |
| [біт 2 оригіналу дослівно] | [біт 2 під клієнта] |
| ... | ... |

Ліва колонка = дослівний транскрипт оригінального відео.
Права колонка = версія під клієнта, вирівняна біт-в-біт.
Посилання + метрика оригіналу завжди у шапці над таблицею.

### Гейти
- **Чесність:** кожна підставлена заявка = правда для клієнта зараз. Не присвоювати чужий результат.
- **On-topic ICP:** змінні з НІШІ клієнта, не тягти чужу тему.
- **ToV:** лексика клієнта, структура/ритм оригіналу не чіпаються.

### Контекст клієнта
Контекст (DNA, voice notes, ніша, ToV) надає ОКРЕМО людина з команди, яка працює зі своїм клієнтом. Цей скіл пояснює лише ПРОЦЕС адаптації.
